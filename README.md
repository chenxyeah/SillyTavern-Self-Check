# 墨提斯之镜 · SillyTavern 写作前置自检

一个用于 SillyTavern 角色扮演的写作前置自检、预设管理、参考资料注入与临时指令插件。

> 当前正式版本：`0.4.0`

## v0.4.0 更新

完整迁入 DEV `0.4.0-beta.22` 的功能，并适配正式版的安装目录、配置、输出标签和更新地址。

- 双 API：独立接口完成自检，再交由酒馆主 API 输出正文，支持模型列表、超时、精简重试与失败回退。
- 上一轮复盘：连续成功的双 API 生成可核对上一轮自检和正文；漏复盘时记录状态，不阻断本轮正文。
- 强力规范：将自检结论转成 YAML，以 System、depth 0 临时注入，正文仍须位于推理标签之外。
- 思维链边界修复：仅在自检提供可靠分界时分开错误包裹的正文；正常推理及酒馆独立保存的 reasoning 数据保留。
- 运行日志：记录单／双 API、题数、正文与复盘结果，错误说明包含具体原因与处理方法。

- 保留资料库、快捷指令、预设导入导出、移动端浮窗与边缘停靠等完整功能。

## 从旧正式版或 DEV 升级

原正式版用户直接更新本仓库即可；插件设置、预设、角色绑定与外观沿用正式版的数据。旧“双阶段严格模式”自动转为单 API，可在设置中另行配置双 API。

如果要继续使用同一酒馆中 DEV 的测试配置：

1. 等待生成结束，更新正式版并刷新页面。
2. 打开“墨提斯之镜 → 插件设置 → 从 DEV 迁入设置”。
3. 确认后会复制 DEV 的预设、角色绑定、资料库、快捷指令、API 配置、日志与外观；自动备份迁入前的正式版设置并立即保存。
4. 正式版启用，DEV 内部开关关闭。请在酒馆扩展页停用 DEV 并刷新页面，之后使用正式版。

如需撤回配置迁入，点击同处的“恢复迁入前的设置”。重复迁入仍保留最初的备份。聊天记录及两版历史自检记录不搬动；API 密钥保存在酒馆设置中，不会加入公开仓库、插件安装包或预设／资料库导出文件。备份也只保存在当前酒馆设置中。

如果 DEV 在另一份酒馆或另一用户档案，迁移按钮无法访问那里的设置；请使用现有预设和资料库导出／导入，再在正式版填写 API 配置。DEV 仓库继续作为开发测试仓库。

## 核心功能

- 每轮正文生成前，强制 AI 先完成用户自定义的自检问答。
- 支持开放问答题与判断题，可设置简短、标准、详细回答。
- “提供剧情/设定依据”默认开启，可逐题关闭。
- 通用预设与角色专属预设可单独启用或叠加使用。
- 角色专属预设可绑定当前角色卡，切换角色时自动切换。
- 支持批量粘贴问题，先在临时识别页面调整，再确认导入。
- 支持自检预设和参考资料库导入、导出与分享；资料库可单独导出，也可批量打包为一个合集文件。
- 支持单 API 与双 API 模式。
- 自检结果保存在插件中，不写入聊天正文；开启双 API 复盘时，会将上一轮相关信息提供给自检 API。
- 自检格式错误时显示提示；完全跳过自检时显示红色感叹号。
- 可测试当前生效问题：AI 只回答问题并给出重复、冲突、模糊等建议，不生成正文。
- 内置参考资料库，可保存文风、强制限制和其他长期资料。
- 参考资料可自动追加成自检问题。
- 内置快捷指令库，支持临时一轮或常开，不写入聊天记录。
- 可选悬浮按钮，支持桌面和移动端拖动、查看最新自检、快速切换快捷指令，并自定义悬浮窗样式、按钮透明度、按钮大小与面板尺寸。
- 自动检查插件自身更新；检测到新版本后可在插件“版本更新”页直接完成更新，并在“版本更新”页查看版本号与更新内容。

## 两种生成模式

### 单 API 模式

只调用一次 API。AI 在同一轮中先输出自检，再输出正文。插件会把自检从聊天消息中剥离，只在管理器和悬浮窗中显示。

### 双 API 模式

在插件设置中填写 OpenAI 兼容接口和密钥、选择模型。独立自检 API 先回答本轮问题，再将结果临时交给酒馆主 API 生成正文。可选择原始问答注入或强力 YAML 规范，并开启上一轮复盘。自检调用、补救重试和正文生成会产生对应 API 用量。

自检失败时，可选择退回单 API 继续正文，或停止本轮生成。复盘需要上一轮成功双 API 来源；回退单 API 的轮次不作为双 API 复盘来源。

## 输出协议

仅当原接口或预设要求可见推理区时，先完整闭合 thinking / reasoning，再输出自检与正文。插件不要求新增或展示内部推理。自检和正文都必须位于推理标签之外：

```text
<thinking>原预设思维链（可选）</thinking>
<stsc_self_check>
<item id="问题ID">
  <answer>最终回答</answer>
  <evidence>具体剧情、角色设定或世界观依据</evidence>
</item>
</stsc_self_check>
正文、状态栏及其他正常输出格式
```

只有勾选“需要依据”的问题强制要求 `<evidence>`。缺少时插件会提示格式有误。

如果推理标签从自检前跨过完整自检块，插件会定向补正边界。如果整段仍被推理标签包住而没有可靠正文起点，插件会保留原文并报警，不猜测分界。正式版使用 `stsc_` 标签；DEV 使用 `stscdev_` 标签，两版各自保留自己的历史记录。

## 推荐隐藏正则（流式模式）

在 SillyTavern 的正则扩展中添加：

```regex
<stsc_self_check\b[^>]*>[\s\S]*?(?:<\/stsc_self_check>\s*|$)
```

替换内容留空。自检结束后，后续正文仍可继续流式显示。

## 注意事项

- 插件检查输出格式与自检完整性，不能保证模型遵循全部指令，也不能证明模型内部推理过程。
- 不同模型的格式遵守能力不同。模型完全跳过自检时，插件会保留正文并显示红色警告。
- “测试预设”、双 API 自检及补救重试会调用额外 API。
- 正式版启用时会关闭同一酒馆中 DEV 的内部开关；建议在扩展页停用 DEV，避免同时操作两版设置。
